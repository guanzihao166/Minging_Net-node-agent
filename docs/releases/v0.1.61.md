# v0.1.61

## Inbound allocation support

- Accept the control plane's `per_inbound` bandwidth allocation protocol.
- Keep token buckets independent per subscriber and inbound, with each inbound
  constrained by its allocated share and its own node ceiling.
- Upload, download and concurrent connections on one inbound consume the same
  allocation; zero allocation pauses traffic and reports demand.
- Replace each subscriber's complete inbound allocation table atomically.
  Missing inbounds receive zero share while that allocation table is active.
- Preserve buckets for unchanged allocations and restore allocations after
  an Xray core rebuild. Reject invalid or inconsistent messages before applying
  any changes.
- A speed-exempt user ignores stale allocation limits once its updated static
  user snapshot arrives.

## Upgrade order

Upgrade Agents to this version first, then deploy the control plane supporting
`per_inbound` and `inbound_id`. Until the control plane is upgraded, existing
static subscriber and node limits remain in effect; legacy aggregate hints
continue to be ignored as in v0.1.60.

Aggregate allocation is sampled and asynchronous. Initial membership discovery,
message delivery and the 100ms token-bucket burst can cause temporary overshoot.
An interrupted control connection retains the most recently applied allocation.

Regression coverage includes independent inbound shares, zero-share demand,
atomic message validation, hot updates, core rebuilds and real VLESS transfers
with upload and download sharing one allocation.
