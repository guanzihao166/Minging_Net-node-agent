# v0.1.62

## Configuration-boundary traffic accounting

- Collect and seal pending runtime traffic under the previously applied
  configuration version before applying a new inbound configuration.
- Serialize collection and configuration switching so delayed traffic reports
  retain the correct inbound identity and historical billing multiplier.
- Leave the previous runtime configuration active when collection or durable
  traffic storage fails; retry rather than relabel old traffic as new traffic.
- Add regression coverage for WAL sealing, collection failure and independent
  same-protocol VLESS listeners with isolated subscriber credentials and limits.

## Upgrade order

Upgrade all Agents to v0.1.62 before the separate control-plane database and
dedicated-inbound cutover. This Agent update does not split inbounds, change
listener ports, alter configured multipliers or initiate a database migration.
Existing identities, configuration, secrets and pending WAL are retained by
the existing checksummed update mechanism.

The pending cutover preserves the existing CDN inbounds for
`cf.877774.xyz:443`; their ports and transport configuration are unchanged.
