# v0.1.52 — automatic kernel BBR selection

Upgraded and newly installed Agents automatically configure Linux TCP congestion
control when their maintenance service starts. No enrollment URL changes are
required. This release builds on the published v0.1.50 source.

- Prefer available or loadable `bbr2`; otherwise select kernel `bbr` and explicitly
  report the fallback. An already selected `bbr3` is preserved.
- Verify the result, attempt rollback on a failed readback, and persist only
  verified settings in an Agent-owned sysctl file.
- Handle missing modules/tools, unsupported kernels, restricted containers,
  read-only filesystems and repeated starts without failing Agent upgrades.
- Use a short root oneshot on systemd, including installations whose existing
  maintenance service protects kernel tunables. OpenRC uses root maintenance.
- Attempt `fq` as the default for future interfaces; retain existing interface
  queue disciplines and shaping rules.
- Leave custom files intact. Full uninstall removes only Agent-owned files.

Linux amd64 and arm64 builds are provided. This feature does not install a kernel
or reboot, cannot supply BBRv2 to a kernel lacking that implementation, and does
not configure UDP/QUIC. Existing TCP sockets retain their existing algorithm.

Validation: full Go tests and vet, Linux execution of the tuning regression
tests, plus the release workflow's Linux tests and both architecture builds.
BBRv2 selection/failure paths are simulated in tests; a real BBRv2 kernel and
every distribution/kernel/container combination have not been field-tested.
